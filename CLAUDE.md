## Project notes

ConnectSphere is an Expo SDK 58 / React Native 0.88 / React 19 social app (iOS, Android, web). Package manager is **npm** (`package-lock.json`), so use `npx`, not `bunx`.

### Commands

```bash
npm start                # expo start (dev server)
npm run ios              # expo run:ios — local dev build (expo-dev-client is installed, so Expo Go is not the target)
npm run android          # expo run:android
npm run web              # expo start --web
npm run lint             # expo lint (eslint-config-expo flat config)
npx tsc --noEmit         # typecheck (strict mode)
```

There is no test runner configured yet.

### Native projects

`ios/` and `android/` exist locally but are gitignored — they are generated by prebuild / `expo run:*`. Change native config in `app.json` (bundle id / package `com.raydedon.connectspheremobile`, URL scheme `connectspheremobile`) and re-generate rather than editing them.

### EAS

`eas.json` profiles: `development` (dev client, internal), `preview` (internal), `production` (auto-incremented build numbers; `appVersionSource: remote`, so versions live on EAS, not in `app.json`).

### Code layout

- `src/app/` — Expo Router routes only. `_layout.tsx` is a single root `Stack` that registers each screen with its title; new screens need a `Stack.Screen` entry there for custom options.
- `src/features/<feature>/` — feature modules (components, types, data) consumed by routes. `feed/` holds `FeedPost` type, `PostCard`, and mock `initialPosts`.
- `tsconfig.json` defines an `@/*` → `./src/*` alias; existing code currently uses relative imports.

### Current state

- No backend: the feed is in-memory mock data, and like/save/tab state lives in `useState` in `src/app/index.tsx`. Refresh is a simulated timeout.
- Unbuilt features (stories, post creation, comments, post options) are stubbed with `Alert.alert(...)` "later milestone" placeholders.
- Styling is plain `StyleSheet.create` with hard-coded hex colors (muted green/neutral palette); there is no theme or design-token module yet. Interactive elements consistently set `accessibilityRole`/`accessibilityLabel`/`accessibilityState` — keep that up.
